# QuQuSQL 確認ポイント・決定待ち事項（TODO）

Phase 1（ワークスペース構築・実装）へ着手する前に、仕様および技術方針について確定しておきたい項目をまとめています。

---

## 1. Oracle データベースの接続方式（決定済み）

- [x] **接続バックエンドの方針を決定する** → **Pure Rust 方式（`oracle-rs`）に決定**

- **決定内容**:
  - Oracle Instant Client 不要・単一バイナリ配布可能な **Pure Rust 方式（`oracle-rs`）** を採用する。
  - `tokio` 非同期ランタイムとネイティブ連携し、起動速度・配布性・省メモリ性を最大化する。
  - 既存の `tnsnames.ora` をそのまま使えるよう、`ququ-core` 側に軽量な `tnsnames.ora` パーサを実装して `host / port / service_name` を自動解決する。
  - ※ 将来的に ODPI-C が必要になった場合でも差し替えられるよう、`ququ-db` のトレイト境界は維持する。

---

## 2. Phase 1 で最初に対応する DBMS の優先順位（決定済み）

- [x] **初期対応 DBMS を決定する** → **Oracle + SQLite に決定**

- **決定内容**:
  - 対応 RDBMS は **Oracle Database（本命・実務用）＋ SQLite（ローカル検証・軽量データ操作用）** の 2 系統とする。
  - Phase 1 から両ドライバ（`ququ-db-oracle`, `ququ-db-sqlite`）を並行構築する。

---

## 3. SQL エディタ基盤の実装アプローチ（決定済み）

- [x] **Phase 1 でのエディタ実装方式を決定する** → **`egui::TextEdit` からの段階移行に決定**

- **決定内容**:
  - **Phase 1**: `egui::TextEdit` ＋カスタム `Layouter`（シンタックスハイライト）で素早く MVP を立ち上げ、実機で操作感を検証する。
  - **Phase 3**: 矩形選択・上部ルーラー・不可視文字の精密描画・大容量 SQL 高速編集のため、`ropey` ベースの独自エディタへ段階移行する。

---

## 4. 仕様の優先度調整（決定済み）

- [x] **必須機能・後回しでよい機能の棚卸し**

- **決定内容**:
  - [x] **PL/SQL 開発支援**: 最初は無し（Phase 4 以降で対応）
  - [x] **接続先パスワードの保存方式**: 最初は **都度入力**（ホスト・ポート・サービス名・ユーザー名等のみプロファイル保存。将来的に資格情報ストア／暗号化保存を検討）
  - [x] **ファイル文字コードのデフォルト**: **UTF-8**（既存ファイルの Shift_JIS / EUC-JP 自動判別・変換保存は引き続き対応）
  - [x] **実行計画の表示形式**: 最初は **インデントテキスト方式**（OSqlEdit 風のテキスト出力。ツリー表形式は将来拡張）
  - [x] **OSqlGrid のマクロ機能**: **最初は不要**（のちのち検討）

---

## 5. 開発環境・ターゲット OS の確認（決定済み）

- [x] **対象 OS・環境を確認する** → **まずは Windows (10 / 11 x86_64) 対応から開始に決定**

- **決定内容**:
  - 初期ターゲット OS は **Windows (10 / 11 x86_64)** とする。
  - フォントは Windows システムフォント（`BIZ UDGothic` / `Meiryo UI` / `Consolas` 等）を優先的に非同期ロードし、バイナリ肥大と起動遅延を防ぐ。
  - 設定ファイル・履歴・キャッシュは Windows 標準ディレクトリ（`directories` クレート経由で `%APPDATA%\QuQuSQL` / `%LOCALAPPDATA%\QuQuSQL`）へ配置する。
  - macOS / Linux 対応は将来の拡張とし、プラットフォーム固有処理は境界を分離しておく。
