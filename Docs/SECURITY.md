# QuQuSQL: セキュリティ＆誤操作防止ポリシー (SECURITY)

本書は、`QuQuSQL` におけるソフトウェアセキュリティ方針およびデータベース実務での事故（情報漏洩・本番データ誤破壊）を防ぐための設計原則を定義します。

---

## 1. メモリ安全性（Rust 採用による基盤保証）

`QuQuSQL` は Pure Rust を主軸として構築されており、Rust の所有権モデルと型システムにより、以下の古典的脆弱性を構造的に排除します。
- バッファオーバーフロー / 境界外アクセス
- Use-After-Free / 二重解放（Double Free）
- 非同期処理間のデータ競合

また、Oracle 接続に C ライブラリ（OCI / ODPI-C）ではなく Pure Rust ドライバ（`oracle-rs`）を採用することで、外部ネイティブ DLL に起因するメモリ安全リスクも最小化します。

---

## 2. 認証情報の安全な取り扱い

- **パスワード非保存（初期方針）**:
  - `connections.toml` にはホスト・ポート・サービス名・ユーザー名などの非機密情報のみを保存し、**パスワードは平文を含めディスクへ一切保存しません**（接続時に都度入力）。
  - メモリ上に保持したパスワード文字列は接続確立後速やかにクリア（ゼロ化）します。
  - 将来的にパスワード保存機能を追加する場合は、Windows 資格情報マネージャ（DPAPI / Credential Manager）等の OS 保護ストレージのみを対象とします。
- **ログ・履歴への機密混入防止**:
  - 実行ログやクラッシュログにパスワード・認証トークンを絶対に出力しません。
- **暗号化通信**:
  - Oracle 接続時の TLS/SSL および Wallet 接続（`oracle-rs` 対応範囲）をサポートします。

## 3. SQL インジェクションおよび本番誤操作防止

- **パラメータ化クエリの徹底**:
  - OSqlGrid の差分更新（`INSERT` / `UPDATE` / `DELETE`）およびバインド変数実行では、文字列連結ではなく **必ずバインドパラメータ** として DB へ送信します。
- **デフォルト手動コミット**:
  - 自動コミットをデフォルト無効とし、意図しないデータ確定を防ぎます。未コミット変更が残っている状態での切断・終了時には警告ダイアログを表示します。
- **本番環境識別と確認ガード（環境区分連動）**:
  - 接続プロファイル登録・ログイン画面で **環境区分（`Production` / `Staging` / `Development` / `Local`）** を明示的に指定します。
  - 選択された環境区分に応じて、**視覚表示（警告バナー・配色）** と **確認ダイアログ・動作制約** が自動的に切り替わります。

### 環境区分（`EnvironmentTier`）別の視覚識別・安全ガード一覧

| 保護項目 | `Development` / `Local`（開発） | `Staging`（検証） | `Production`（本番） |
| :--- | :--- | :--- | :--- |
| **接続一覧での分離（誤接続防止）** | 青/緑バッジ `[開発]` `[ローカル]` | 黄〜オレンジバッジ `[検証]` | **赤枠の独立セクション＋`[本番]` バッジ**（任意でデフォルト折りたたみ）、接続ボタンも `⚠ 本番環境へ接続` に変化 |
| **接続後の視覚識別** | 青/緑系の細アクセントライン | 黄〜オレンジ系アクセント＋バッジ | **赤系の警告バナーを画面上部に常時表示**（`⚠ 本番環境に接続中`）＋ステータスバー強調 |
| **接続時の初期モード** | 通常（読み書き可） | 通常（設定で Read-Only 可） | **デフォルト読み取り専用（Read-Only）** で接続（更新時は明示的にロック解除が必要 ※プロファイル変更可） |
| **`COMMIT` 実行時** | 即時実行 | 確認ダイアログ（設定可） | **強制確認ダイアログ必須**（「本番環境です。本当にコミットしますか？」＋未コミット件数表示、デフォルトフォーカス＝キャンセル） |
| **DML 実行前** | `WHERE` なし更新のみ警告 | 確認ダイアログ（設定可） | **実行前確認ダイアログ必須**（対象 SQL 要約を表示） |
| **DDL 実行前** | 未コミット時のみ警告 | 確認ダイアログ必須 | **厳格な確認ダイアログ必須**（暗黙コミット警告＋デフォルトフォーカス＝キャンセル） |
| **グリッド Apply 時** | SQL プレビュー確認 | SQL プレビュー確認 | **本番警告付き SQL プレビュー確認必須**（`SAVEPOINT` 保護） |
| **ショートカット誤爆対策** | 通常動作 | 確認ダイアログ経由 | **ワンキー即確定を禁止**（必ずダイアログ経由、誤 `Enter` 連打で確定しない） |

## 4. データ破損・不意なコミット防止の絶対原則（Safety Invariants）

データベースのデータ破壊や想定外更新を防ぐため、実装全体を通じて以下の安全不変条件を厳守します。

1. **アプリ側からの暗黙 `COMMIT` を一切禁止**:
   - 接続確立時は常に手動トランザクションモードとし、ユーザーの明示的な `Commit` 操作以外でアプリが `COMMIT` を発行するコードパスを実装しない。
2. **Oracle の DDL による「暗黙コミット」の事前検知・警告**:
   - Oracle では `CREATE` / `ALTER` / `DROP` / `TRUNCATE` 等の DDL 実行時にサーバー側で暗黙の `COMMIT` が発生する。未コミットの DML が存在する状態で DDL を実行しようとした場合、実行前に警告ダイアログで必ず確認を求める。
3. **終了・切断ダイアログの安全なデフォルトフォーカス**:
   - 未コミット変更がある状態での終了・切断確認ダイアログでは、誤って `Enter` キーを押しても確定されないよう、デフォルトフォーカスを「キャンセル（閉じない）」に固定し、「コミットして終了」をデフォルトにしない。
4. **`WHERE` 句なし `UPDATE` / `DELETE` の実行前ガード**:
   - SQL エディタから `WHERE` 句のない `UPDATE` / `DELETE` を実行しようとした場合、全件更新・全件削除の事故を防ぐため、環境を問わず確認ダイアログを表示する（設定で明示解除しない限り有効）。
5. **グリッド一括反映（Apply）の `SAVEPOINT` 保護と更新件数検証**:
   - グリッド編集の Apply 時は開始前に `SAVEPOINT` を設定し、各行の `UPDATE` / `DELETE` の影響行数が **厳密に 1 件** であることを検証する。途中でエラーまたは件数不一致（0 件 / 2 件以上）が発生した場合は、`ROLLBACK TO SAVEPOINT` で Apply 全体を安全に巻き戻す。
6. **未変更カラム非接触・高精度型保持**:
   - グリッドからの `UPDATE` は変更されたカラムのみを `SET` 句に含め、`DATE` や `NUMBER`（`Decimal(CompactString)` で厳密保持）の意図しない丸めや書式破壊を防ぐ。
7. **段階的な実機検証**:
   - DML 実行・トランザクション制御・グリッド差分更新は、まず SQLite インメモリ／ローカルテスト DB での網羅的な自動テスト（[TESTING.md](./TESTING.md)）を通過させてから、Oracle 検証環境で慎重に確認する。
